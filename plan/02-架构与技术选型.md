# plan/02 · 架构与技术选型

> 上游：`plan/01-题目文档.md`（五模块）· `data/README.md`（M1 字段语义结论）
> 版本：v1 · 2026-10-16

## 一、技术选型（含弃选项与理由）

| 维度 | 选型 | 弃选项与理由 |
|---|---|---|
| 语言 | Python，**底线 3.8**（本机实测 3.8.8 + 3.12 双通道） | 弃 Node/TS：日志解析是长文本 + 正则 + JSON 流处理，Python 标准库更直接；且本机双解释器通道便于跨版本验证 |
| 运行时依赖 | **零第三方依赖**（仅标准库 `json`/`pathlib`/`re`/`html`/`argparse`/`sqlite3`） | 弃 pandas：引入即失去"纯净可审计"定位，且聚合规模（本机 45MB 级）标准库 `dict`+`sqlite3` 足够 |
| 聚合引擎 | 标准库 `sqlite3` 内存库 + SQL 聚合 | 弃"纯 Python 双重循环手写聚合"：题目模块 2 明写"确定性 SQL 风格聚合"，`sqlite3` 是**确定性**的（同输入同结果），且 SQL 可读可审 |
| 报告渲染 | 自写最小 Markdown / HTML 渲染器（单渲染源） | 弃 Jinja2/模板引擎：为满足"人读 + 机读双轨、两格式内容一致是结构性质（单一渲染源）"，自写渲染器可控且零依赖；HTML 无外链（内联 CSS） |
| 报告数据交换 | 自写 `serialize.py` 统一写盘（`sort_keys=True` + `ensure_ascii=False` + LF + 结尾换行 + 原子写） | 弃各子命令各写 `open()+json.dump()`：见 data/README 纪律，"换一个子命令写盘形态会变吗"= 迟早漂移 |
| LLM | **不使用**（任何环节） | 题目明写不做 AI 评分；所有统计=确定性计数，归因=规则匹配 |
| CLI 框架 | 标准库 `argparse` | 弃 click/typer：零依赖纪律；`argparse` 的 `build_parser()` 可被测试反射（README↔CLI 对账守门需要） |
| 打包 | `setuptools` + src 布局；console script `<pkg> = opslens.cli:main` | 弃 flat 布局：src 布局天然防"源码态 CWD 恰在 sys.path 上"的假绿（安装面第四面） |
| 冻结产物 | 首期不承诺 exe（扩展项） | 纯 CLI + 源码包；如后续加打包，按 skill 阶段 7 多平台条执行 |

**关键选型纪律**：`sqlite3` 聚合的 SQL 语句与列名**必须**来自 `plan/03` 的单一口径定义，不得在报告层出现第二份计算。

## 二、分层架构（单向依赖，禁止反向）

```
                    ┌───────────────────────────────┐
   CLI 层            │ cli.py（argparse + 退出码语义）│
                    └───────────────┬───────────────┘
                                    │ 只调编排层，零判定
                    ┌───────────────▼───────────────┐
   编排层            │ pipeline.py（scan→aggregate→  │
                    │   attribute→report 四阶段编排）│
                    └───────────────┬───────────────┘
                                    │
        ┌───────────────┬───────────┴────────┬────────────────┐
        ▼               ▼                    ▼                ▼
  ┌──────────┐   ┌────────────┐      ┌─────────────┐   ┌────────────┐
  │ 解析层    │   │ 聚合层      │      │ 归因层       │   │ 报告层      │
  │ parsers/ │──▶│ aggregate  │─────▶│ attribute   │──▶│ report/    │
  │          │   │ (sqlite3)  │      │ (规则匹配)   │   │ (渲染)      │
  └────┬─────┘   └────────────┘      └──────┬──────┘   └─────┬──────┘
       │                                     │                │
       ▼                                     ▼                ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │ 基础层：schema.py(统一 IR) / config.py(阈值·口径参数) /            │
  │         serialize.py(确定性写盘) / _encoding.py(UTF-8 守卫) /      │
  │         exit_codes.py / rules.py(规则包加载 + status 门控)         │
  └──────────────────────────────────────────────────────────────────┘
       ▲                                                              ▲
       │  只读                                                         │
  data/rules/*.json（阈值表、失败模式表、口径参数）   本机日志（只读，不落仓）
```

**依赖方向铁律**：
- 基础层**不 import** 任何上层；解析层**不 import** 聚合/报告层；报告层**只消费结论、零判定**（重算任何统计 = 违规）。
- 解析层是**纯函数**：`parse_*(path, ...) -> list[Event]`，**不读规则包**、**不读时钟**、**不写盘**。规则包以**参数**注入（防 petfood "宣称词表硬编码在解析层"的第二份口径）。
- 报告层**不读规则包**（判定与阈值已在归因层落成结论字段），防"渲染层重算判定"。

## 三、统一中间表示（IR）：`ToolCallEvent`

五模块的共同契约，定义在 `src/opslens/schema.py`（**唯一出处**）：

| 字段 | 类型 | 说明 | 缺失语义 |
|---|---|---|---|
| `source` | `"claude_code"` / `"codex"` | 数据来源，跨源不混算 | 必填 |
| `source_version` | `str` | Claude: 顶层 `version`；Codex: `session_meta.cli_version` | `""` = 未声明 |
| `session_id` | `str` | 会话标识 | 必填 |
| `seq` | `int` | **源行号**（不是数组下标）→ 保证排序确定 | 必填 |
| `timestamp` | `str` | 原样 ISO 字符串（**不解析成 datetime，不读时钟**） | `""` = 缺失 |
| `server` | `str` | Claude: `mcp__<server>__<tool>` 取 server；非 `mcp__` → `"<builtin>"`；Codex: `"<codex>"` | 必填 |
| `tool` | `str` | 工具名 | 必填 |
| `call_id` | `str` | 关联 tool_use ↔ tool_result | `""` = 无法关联 |
| `status` | `"ok"` / `"error"` / `"unknown"` | **三态**，判定口径见 data/README §五 A/E | 缺失 → `unknown` |
| `error_text` | `str` | 失败时的错误文本（成功时 `""`） | `""` |
| `tokens` | `Tokens` | `input` / `output` / `cache_read` / `cache_creation`，**四项分列不合并** | 缺失 → `None`（≠ 0） |
| `duration_ms` | `Optional[int]` | **仅 Codex 可得**（`Wall time`）；Claude 侧首期不可得 | `None` = 不可得 |
| `turn_tokens_attributed` | `bool` | token 是否为"调用轮次归属"（Claude=True / Codex=False） | 必填 |
| `notes` | `list[str]` | 次生信号（`interrupted` / `stderr_nonempty` / `unrecognized_field` 等），可审计 | `[]` |

**`unknown` 是第一位公民**：`status=unknown` 与 `tokens=None` **不得**被下游静默当作 `ok` / `0`。模块 2 的每个计数都必须同时输出 `ok / error / unknown` 三个数 + `token_samples`（实际参与 token 聚合的样本量）。

## 四、确定性与可复现设计（贯穿全链）

| 环节 | 确定性来源 | 守门 |
|---|---|---|
| 事件排序 | `(source, session_id, seq)` 三元组排序，`seq` = 源行号 | 双跑 IR JSON 逐字节一致测试 |
| 时间 | **全程不读系统时钟**；`timestamp` 只作字符串透传与排序键 | 扫描测试：产物无时间戳字段 |
| 数值 | 阈值/窗口/模式表全部来自 `data/rules/*.json`，代码零字面量 | 零字面量门禁（扫描 `src/` + `tools/`，含 docstring/注释） |
| 写盘 | 唯一入口 `serialize.write_atomic()`：`sort_keys=True` / `ensure_ascii=False` / LF / 结尾换行 / 原子 rename | 同输入双跑逐字节一致；写盘入口唯一性 AST 守门 |
| 随机 | **禁 `random` / `uuid` / `time`**（合成生成器用自研 splitmix64，固定 seed） | AST 扫描禁用模块 |
| 编码 | 入口 `_ensure_utf8_stdio()` + 子进程显式 `encoding=` + CI `PYTHONUTF8=1` | 三通路各自测试（本机 `-X utf8` 证明不了子进程/CI） |

## 五、隐私边界（架构级）

- **只读**：所有数据源以 `mode="r"` 打开，**永不写入**用户目录；无任何网络调用（`socket`/`urllib`/`requests` 零 import，AST 守门）。
- **`env` 是禁读键**：`~/.claude/settings.json` 的 `env` 块含活体凭据（M1 实测）。解析器**按显式键白名单读取**（`permissions.allow` / `enabledPlugins`），**`env` 永不进入任何数据结构**（比"读了不打印"更强）。
- **`prompt` / 代码正文永不落产物**：`tool_use.input`（可能含源码/参数）**不复制进 IR**；`error_text` 走**截断 + 模式提取**（首行 + 分类标签），报告只出分类标签与截断片段，不出全文。
- **真实日志不入仓**：`.gitignore` 已排除；`data/synthetic/` 只用 `fake-server` 白名单命名；配"仓内产物扫描不含真实 server 名/绝对路径"守门。

## 六、退出码语义（M0 定稿，锁进测试）

| 码 | 语义 | 触发 |
|---|---|---|
| `0` | 成功 | 命令正常完成 |
| `1` | **运行完成但检出问题**（如：解析到 `unknown` 态超阈值、建议命中"建议移除"）— **不是跑挂** | 见各子命令声明 |
| `2` | 用法错误 / 未知名 / 参数非法（如 `--since` 非法、样本不足 ≥ 硬失败阈值） | argparse 错误、显式 `raise UsageError` |
| `3` | **阶段未就绪**（骨架期占位：模块未实现，**不伪造空结果**） | 骨架期 `scan`/`aggregate`/`report` |
| `4` | **数据不可用**（数据源目录不存在 / schema 版本不识别） | 解析层前置检查 |

> `3` 是**退役型语义**：M2/M3/M5 落地时**整项退役**（删常量 → 改 CLI/测试（含 `not hasattr` 防复活）→ 改文档退出码表 → 改决策记录，四处同步）。
> 与 skill "退出码语义会随能力解锁而退役"条同源；`not hasattr` 断言防幽灵语义复活。

**安装面纪律**（skill "安装面第四面"）：`src/` 布局 + `package-dir = {"" = "src"}`；README 快速开始的那条命令（`pip install -e ".[dev]"`）**必须**让 `opslens` 与 `tests/` 全部可 import；CI 同时跑 `python -m opslens` 与**裸 `opslens`**（两条通路 `sys.path` 来源不同）。

**已实测的安装面事实与一处如实的缺口（M0 实跑记录）**：
- ✅ `pip install -e ".[dev]"` 在干净 venv 里成功；`opslens --version`、**裸 `opslens --help` 在中立目录**（非仓库根）均正常；默认规则目录解析为仓库内 `data/rules`（实测存在）。
- ⚠️ **缺口（如实登记，M5/M6 前解决）**：`config.default_rules_dir()` 按"包外三级"定位 `data/rules`，**该解析只对源码态 / editable 安装成立**；若将来以 wheel 形式安装（数据目录不在包内），默认路径会解析不到 → 需 `--rules-dir` 显式指定，或把规则包收进包数据（`package-data`）。**首期发布物是源码包 + editable 安装**，故该缺口不影响 README 快速开始；**M6 发布前要么把 `data/rules` 纳入打包数据，要么在 README"已知环境问题"节写明 wheel 安装需显式传 `--rules-dir`**。此项**不得**在 M6 留档里被写成"已验证 wheel 安装"。
