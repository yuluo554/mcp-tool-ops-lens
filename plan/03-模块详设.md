## 模块 1 · 会话日志与配置解析

**职责**：把异构日志解析为统一 IR `ToolCallEvent`（见 plan/02 §三）。**纯函数、不读时钟、不读规则包、不写盘。**

### 1.1 三个解析器

| 解析器 | 输入 | 产出 | 关键字段映射（M1 已核对） |
|---|---|---|---|
| `claude_jsonl.py` | `~/.claude/projects/*/*.jsonl` | 事件流 | `tool_use`(id/name) × `tool_result`(tool_use_id/is_error/content) 按 `call_id` 关联；`message.usage` 记轮次 token；`version` → `source_version` |
| `claude_config.py` | `~/.claude.json`、`~/.claude/settings.json`、`~/.claude/plugins/installed_plugins.json` | **配置侧事实**（非事件流） | `mcpServers`（全局 + 按 project 分列的 `projects[].mcpServers`）；`projects[].lastToolDuration`；settings **只读 `permissions.allow` / `enabledPlugins`，`env` 禁读** |
| `codex_rollout.py` | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` | 事件流 | `session_meta.cli_version` → `source_version`；`function_call`/`custom_tool_call` → 调用；`*_output` 的 `Exit code:` 文本 → 成败；`Wall time:` → `duration_ms`；`event_msg/token_count` → **会话级**token（不摊到单调用） |

### 1.2 schema 版本检测（题目"技术创新"锚点）

- **检测键**（M1 实测确定）：Claude = 顶层 `version`（实测 7 个：2.1.216/220/223/226/233/238/263）；Codex = `session_meta.cli_version`（实测 `0.146.0-alpha.3.1`）。
- **已支持版本集**：`src/opslens/parsers/versions.py` 内的**显式常量集合**（不是正则放宽匹配）。解析时该键**不在集合内** → **报错**（`exit 4`）+ 打印"未识别版本 + 期望集合 + 检测键路径"，**绝不静默按最宽松规则解析**（静默错解正是题目点名要防的）。
- **字段级守卫**：出现 IR 未覆盖的**新字段形态**（如 tool_result 出现新的 `is_error` 型值）→ 计 `notes` 注记 + 该字段降级 `unknown`，**不猜**。
- 配套测试：版本不在集合 → 断言 exit 4 且 stderr 含检测键路径；**变异验证**（把版本集合改成万能匹配 → 测试必红）。

### 1.3 目录前置检查

- 数据源目录不存在 / 为空 → **exit 4**（不是 0，也不是静默空报告）。`--home` 可显式指定（**测试与演示一律显式传临时目录**，防误扫真实用户数据——skill "可缺省参数≠测试可以不传"条）。

## 模块 2 · 工具调用统计聚合

**职责**：确定性 SQL 聚合，**无任何模型参与**。

### 2.1 聚合维度与指标（唯一口径表）

| 指标 | 定义 | 三态处理 |
|---|---|---|
| `calls_total` | 该维度事件总数 | — |
| `calls_ok` / `calls_error` / `calls_unknown` | 按 `status` 三分 | **三者相加 = calls_total**（对账等式，锁进测试） |
| `failure_rate` | `calls_error / (calls_ok + calls_error)` | **`unknown` 不进分母**（data/README §五 A：缺失态≠成功）；分母为 0 → `null` + `insufficient_data=true` |
| `retry_count` | 同 server+同 tool 在**时间窗**内连续失败后再次调用，记一次重试 | 窗口值取 `params.json`（**不写死代码**） |
| `tokens_input` / `tokens_output` / `tokens_cache_read` / `tokens_cache_creation` | 四项**分列求和**，不合并 | `tokens=None` 的样本剔除 + 单列 `token_samples`（实际参与数）与 `token_missing` |
| `turn_token_avg` | 上述 token 之和 / `token_samples` | 名称用 **`turn_` 前缀**，明确"轮次归属"（见 data/README §五 B） |
| `duration_avg_ms` | `duration_ms` 非空样本均值 | **Claude 侧全不可得 → `null` + `duration_available=false`**；不与 Codex 混算 |

### 2.2 两级维度

- **server 级**：`GROUP BY source, server`
- **tool 级**：`GROUP BY source, server, tool`
- 两级都必须**输出 `unknown` 计数**，并在报告中可见（"未声明"不得看起来像"没问题"）。

### 2.3 实现纪律

- `sqlite3` 内存库（`:memory:`），建表 → 灌 IR → SQL 聚合。SQL 列名与上表**一一对应**。
- **口径唯一性守门**：AST 扫描断言"除法运算 `BinOp(Div)` **只出现在 `aggregate.py` 与 `attribute.py` 与 `tests/`**"——防报告层或 CLI 层出现第二份比率计算（skill "数值口径只有一处要落成可证伪守门"条）。
- **重试识别与耗时口径在本文定义一次**，模块 1/3 引用不重写（题目 §二 模块 2 纪律）。

## 模块 3 · 失败模式归因

**职责**：对失败调用做**规则匹配**分类（**非 AI 评分**）。

### 3.1 分类标签（题目指定五类）

`timeout` / `permission_denied` / `invalid_args` / `content_refusal` / `other`

### 3.2 规则表（`data/rules/failure_patterns.json`）

每条规则结构（**模式表入库、可审计**）：

| 字段 | 说明 |
|---|---|
| `id` | 规则 id |
| `category` | 上述五类之一 |
| `patterns` | 正则模式列表（**文字模式，非模型**） |
| `verified_samples` | **已核对样例**（≥1 条实测错误文本摘录）——**空则该规则不得生效** |
| `status` | `verified` / `pending` |

**题目纪律的落法（硬门）**：`verified_samples` 为空或 `status != "verified"` 的规则**不得进入计算路径**，匹配落 `other`；且"未生效规则"要在报告中**显式列出原因**（skill "未启用不冒充通过" + "缺锚点的规则不得被引擎加载"同源）。

### 3.3 归因产出

```json
{"category": "timeout", "rule_id": "F-TO-1", "matched_pattern": "...", "sample_count": 12}
```

- 每类计数 + 各类**未命中（落 `other`）**的计数单列。
- **M1 实测的可用模式源**：Claude 侧 `is_error=true` 的 `content`（实测样本含 `Exit code 49`、`SyntaxError`、`Traceback ... websocket`）；Codex 侧 `Exit code: 124`（超时惯例值）。**这些是模式表的候选素材，进表前需按 3.2 挂 `verified_samples`。**

## 模块 4 · 删换建议报告

**职责**：由模块 2/3 结果按**阈值规则**产出**建议**（**建议 ≠ 自动修改**，**绝不改用户配置**）。

### 4.1 建议类型与阈值（全进 `data/rules/thresholds.json`，可调）

| 建议 | 触发（阈值全部可配） | 必附证据 |
|---|---|---|
| `remove_candidate`（建议移除） | `failure_rate ≥ T_fail` **且** `calls_total ≥ N_min` | 失败率 + 分子分母 + 样本量 |
| `investigate`（建议排查） | `T_warn ≤ failure_rate < T_fail` | 同上 |
| `cost_heavy`（开销大户） | `turn_token_avg ≥ T_tok` **且** `token_samples ≥ N_tok` | 均值 + 参与样本数 + 缺失数 |
| `low_signal`（数据不足） | `calls_total < N_min` 或 `token_samples < N_tok` | **显式降级为"数据不足"**，不出建议 |

**题目纪律的落法（硬门）**：
- 每条建议**必须**显示：口径名称、阈值取值、分子/分母、样本量。缺任一项 → 该条建议**不输出**（视为内部错误）。
- 样本不足**一律降级"数据不足"**，绝不因小样本给出"建议移除"。
- 阈值不写死在代码：`thresholds.json` + `--config` 覆盖；**零字面量门禁**扫描 `src/`（含 docstring/注释）不得出现阈值数值。

### 4.2 报告产物（人读 + 机读双轨，单一渲染源）

| 产物 | 格式 | 说明 |
|---|---|---|
| `report.json` | JSON（机读） | 单一渲染源（所有结论的**唯一**结构化出处）；`serialize.write_atomic()` 写盘 |
| `report.md` | Markdown（人读） | 由 `report.json` 渲染 |
| `report.html` | HTML（人读） | 由 `report.json` 渲染；**内联 CSS，零外链**（断网可开） |

- **结构性质**：`report.md` / `report.html` 的每个数字都来自同一份 `report.json` → "两格式内容一致"是**结构性质**，不是人工比对。
- **渲染层零判定**：`report/` **不读规则包、不算比率**（AST 守门：`report/` 内无 `BinOp(Div)`、无规则包 import）。
- **必须包含的章节**：① 数据来源与覆盖声明（扫了哪些路径、哪些源、schema 版本）；② `unknown`/样本缺失独立分区（**不混入统计**）；③ 建议清单（每条附口径+样本量）；④ 未生效规则清单（原因）；⑤ 定位宣言 + "建议仅供参考，不自动修改配置"声明。

## 模块 5 · 真值基准

**职责**：合成日志 + **程序化植入真值** → 引擎输出 vs 真值对账。

### 5.1 合成生成器（`tools/gen_synthetic_logs.py`）

- **自研确定性 RNG**（splitmix64，固定 seed）：**禁 stdlib `random` / 禁 `set` 迭代序 / 禁系统时钟**。
- **假 server 名白名单**：`mcp__fake-server__*`（+ 第二三个虚构 server 名），**绝不混入真实 server 名**（本机真实名如 `windows-mcp`/`desktop-commander`/`codegraph`/`officecli`/`fetch`/`memory`/`time` → 进**禁止词表**，扫描守门）。
- **真值库只存"输入与期望"**：真值 JSON 里**不得出现 `observed` 一类字段**（skill 明判：真值库出现"观测"即红——冻结观测会让引擎全坏也全绿）。观测由基准**运行时实算**。
- **产出**：`data/synthetic/logs/*.jsonl`（Claude 形态 + Codex 形态）+ `data/synthetic/truth.json`（植入真值）。
- **位级确定性**：两次生成逐字节一致（`--check` 通路）；产物**无时间戳**。

### 5.2 真值内容（植入即真值）

| 植入维度 | 最低覆盖项（写进 manifest） |
|---|---|
| server 失败率 | 高（如 ~60%）/ 中（~25%）/ 低（~5%）/ **正常重试型**（失败但被重试成功） |
| 失败模式 | `timeout` / `permission_denied` / `invalid_args` / `content_refusal` **四类各至少 1 条** + `other` 类 |
| 三态 | `ok` / `error` / **`unknown`（is_error 缺失）各至少 1 条**（M1 实测出的形态必须进基准） |
| 边界 | **卡阈值**（恰好 = `T_fail`，验 `≥` 语义）/ **near_miss**（差一点不到阈值，验"不到不命中"） |
| 反向 | **不该建议移除的 server**（低失败率）——只测"该命中"则阈值方向写反永远不红 |

### 5.3 对账与覆盖度声明

- 按 server 维度 + 失败模式维度**分套件对账**；每套件配**可证伪探活**（注入缺陷 → 必须报未达标：如把 `is_error=True` 判成 `ok`，基准必红）。
- **覆盖声明总数/采样数双登记**（manifest 逐形态"规则包总数/采样数/清单"）+ 显式"抽样覆盖非穷举"。
- **"未启用"套件不冒充通过**：空分母 → `not_enabled=true` + notes + `exit 1`。
- 退出码三语义锁进测试（`0` 达标 / `1` 未达标 / `2` 用法与未知名错误）。

## 五模块闭环验收链（M4 定稿）

```
tools/gen_synthetic_logs.py  →  data/synthetic/{logs,truth.json}
        │                                    │
        ▼                                    ▼
  [模块1 解析] ──IR──▶ [模块2 聚合] ──▶ [模块3 归因] ──▶ [模块4 报告]
        │                                    │              │
        └──────────── 对账 ◀─────────────────┘        示例报告（MD+HTML）
                    [模块5 基准：引擎输出 vs 植入真值]
```

**闭环判据（M4 出口门）**：模块 5 对账报告在**全维度**上"引擎输出 == 植入真值"；任一形态不等 → 未达标（exit 1）且差异条目逐条列出。
