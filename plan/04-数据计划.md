## 二、隐私红线（数据侧，四条硬约束）

1. **零上传、零遥测**：代码内 `socket` / `urllib` / `http` / `requests` **零 import**（AST 守门断言），断网可跑。
2. **真实日志不入仓**：`.gitignore` 排除真实日志目录；`data/synthetic/` 只用 `fake-server` 白名单命名；配**禁止词表扫描守门**（本机真实 server 名 `windows-mcp` / `desktop-commander` / `codegraph` / `officecli` / `fetch` / `memory` / `time` 出现在仓内任何文件 → 红）。
3. **凭据禁读**：`settings.json` 的 `env` 块（实测含 `ANTHROPIC_AUTH_TOKEN`）**永不读取**；解析器按显式键白名单取键。配守门：解析器源码**不含 `"env"` 字面量的取值路径** + 测试用含假凭据的 fixture 断言产物**不含**该值。
4. **prompt / 代码正文不落产物**：`tool_use.input` 不进 IR；`error_text` 经**空白归一**（多行折叠为单行）后按上限截断再进 IR/报告（K16；M3 修正：早期"只取首行"会丢掉第二行起的失败签名）。

## 三、合成数据规格（模块 5 的输入）

### 3.1 生成器契约

| 项 | 规格 |
|---|---|
| 入口 | `tools/gen_synthetic_logs.py`（**编码守门覆盖**） |
| 确定性 | 自研 splitmix64，`--seed` 固定；`--check` = 重新生成并与盘中比对，逐字节一致 |
| 输出 | `data/synthetic/logs/{claude_alpha.jsonl, codex_alpha.jsonl}` + `truth.json` + `manifest.json` |
| 禁用 | stdlib `random` / `set` 迭代序 / 系统时钟 / 时间戳字段 |
| 命名白名单 | server 一律 `fake-*`（如 `fake-high-fail` / `fake-mid-fail` / `fake-low-fail` / `fake-retry`），tool 一律 `tool_*` |
| 规模 | 每 server ≥ `N_min + 2` 条（保证有跨阈值的可判样本）；总量控制在百条级（入仓友好、审阅友好） |

### 3.2 真值植入清单（`truth.json` 只存输入与期望）

```json
{
  "seed": 20261016,
  "servers": [
    {"server": "fake-high-fail", "calls_total": 40, "calls_error": 24, "calls_ok": 16, "calls_unknown": 0,
     "expected_failure_rate": 0.6, "expected_suggestion": "remove_candidate",
     "failure_categories": {"timeout": 12, "invalid_args": 12}}
  ],
  "boundary_cases": [
    {"server": "fake-threshold-exact", "note": "failure_rate 恰等于 T_fail，期望命中（验 ≥ 语义）"},
    {"server": "fake-near-miss", "note": "差一点不到 T_fail，期望不命中"}
  ],
  "reverse_cases": [
    {"server": "fake-low-fail", "note": "低失败率，期望不出 remove_candidate（反向样例）"}
  ]
}
```

> **禁止**在真值中出现 `observed_*` / `engine_output` 一类字段——那会让"引擎全坏也全绿"（观测必须由基准运行时实算）。

### 3.3 覆盖度口径（进 `manifest.json`）

| 维度 | 最低覆盖项 | 已覆盖形式 | 总数/采样数 |
|---|---|---|---|
| server 失败率 | 高 / 中 / 低 / 重试型 | 4 个 fake server | 逐项登记 |
| 失败模式 | timeout / permission_denied / invalid_args / content_refusal | 4 类各 ≥1 | 逐项登记 |
| 三态 | ok / error / unknown | 各 ≥1 | 逐项登记 |
| 阈值边界 | threshold_exact / near_miss | 2 个 | 逐项登记 |
| 反向 | 不该命中的 server | ≥1 | 逐项登记 |

**声明**："抽样覆盖，非穷举"必须显式写出。

## 四、数据流向与口径纪律

```
本机日志（只读）───┐
                   ├─▶ 模块1 解析 ─▶ IR 事件流 ─▶ 模块2 聚合 ─▶ 模块3 归因 ─▶ 模块4 报告
合成日志（入仓）───┘                                                              │
        ▲                                                                        │
        └──────────────── 模块5 基准：引擎输出 vs 植入真值（运行时实算观测）◀────┘
```

- **口径一处定义**：`data/README.md` §四 + §五 E（成败/token/耗时/重试）+ `plan/03` §2.1（指标定义）。**任何第三处手写第二份口径 = 违规**。
- **阈值全在配置**：`data/rules/thresholds.json`（可被 `--config` 覆盖）；**零字面量门禁**扫描 `src/`（含 docstring/注释）。
- **规则 status 门控**：`failure_patterns.json` 中 `status != "verified"` 或 `verified_samples` 为空的规则**不进计算路径**，落 `other` 并在报告"未生效规则"节列出原因。
