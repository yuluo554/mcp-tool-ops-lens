  1. **错误文本首行截断丢失败签名**：`common.truncate_error_text` 原取"首行"，但两侧日志的失败信号
     都在**第二行及之后**（Claude 的 `Command timed out after` 跟在 `Exit code 143` 后；Codex 的
     `Exit code: 124` 跟在 `Script failed` 后）。只留首行时，规则表这两条模式**永远无法命中**，
     归因必然与真值不符（实测 timeout 全部落 `other`）。**修正为空白归一**（多行折叠为单行后再截断），
     保住签名且保持"单行 + 上限"的隐私形态。守门：`test_error_text_is_whitespace_normalized_not_first_line_only`
     + `test_timeout_rule_actually_matches_multiline_error_text`；变异项 23。

     "只有重试型 server 有 8 次，其余为 0"——**期望值不可复算**（违反 K12 的"观测由基准运行时实算"精神）。
     **修正生成器调用节奏**：重试型 server 间隔落在窗口内（3s），其余落在窗口外（200s）；
     `expected_retry_count` 改为**由实际生成的调用序列 + 窗口规则复算**（与引擎 SQL 实现相互独立）。
     守门：生成器 `_validate_retry_separation` 自校验 + `test_retry_count_matches_truth_per_server`
     + `test_retry_window_change_changes_the_count`；变异项 24。
  - **两处修正后 `truth.json` / `manifest.json` 内容不变**（修正的是"期望值的可推导性"，不是期望值本身）；
    `claude_alpha.jsonl` 仅时间戳字段变化（逐字节 diff 392 行全为 timestamp）。
- **口径唯一性白名单含真值生成器**：`plan/03 §2.3` 原文只写"只出现在 `aggregate.py` / `attribute.py` / `tests/`"。
  实现时发现 `tools/gen_synthetic_logs.py` 必须推导**期望值**（`_round_rate` / `expected_failure_rate`），

  故白名单扩为三处并**逐条写明理由**（见 `tests/test_aggregate.py::DIV_ALLOWED_FILES`）。
  这是对 §2.3 措辞的**扩充而非放宽**：白名单里的每一处都被单独论证过，且新增落点需改测试才生效。
