## 三、边界与非目标对标（题目 §六，逐条有守门）

| 边界 | 落成什么 | 守门 |
|---|---|---|
| 不做 MCP 管理/安装/同步 | 无任何写配置/安装逻辑 | AST：无写盘到用户目录的函数调用路径 |
| 不修改用户配置 | 只读打开 + 建议文本 | 打开模式断言 `"r"`；无 `open(..., "w")` 指向用户目录 |

| 格式漂移风险（只声明 Claude Code + Codex） | schema 版本检测 + 未识别即报错 | M2 版本集测试 + 变异验证 |

## 五、决策记录

| 日期 | 决策 | 结论 / 弃选项理由 |
|---|---|---|
| 2026-10-15 | 定向、弃管理侧、弃 AI 评分、弃全覆盖、定纯本地 CLI | 见 `plan/00-README总览.md` 决策记录表 |
| 2026-10-16 | **成败判定改为三态**（`ok`/`error`/`unknown`） | M1 实测：`is_error` 缺失占约 50%，其中 14.9% 含错误文本 → 二分会把真实失败洗成成功。**推翻题目文档"失败判定=is_error 标志"的默认假设** |
| 2026-10-16 | **token 口径定为"调用轮次归属"**，Claude 四项分列、Codex 不摊到工具 | M1 实测：token 在 assistant 消息上（覆盖率 100%），不在工具结果上；Codex `token_count` 是会话/轮级，与单次调用无绑定 → 摊算 = 产出假结论 |
| 2026-10-16 | **耗时：Claude 侧首期声明"不可得"** | M1 实测：Claude jsonl 无按工具耗时字段；`lastToolDuration` 只是"最后一次"项目级值 → 不得冒充 |
| 2026-10-16 | **`settings.json` 的 `env` 定为"禁读键"** | M1 实测：`env` 含活体 `ANTHROPIC_AUTH_TOKEN`；白名单键改为 `permissions.allow` |
| 2026-10-16 | **白名单键位勘误**：MCP 工具白名单在 `permissions.allow` | 实测 settings.json 无 `allowedTools`/`mcpServers` 键；题目文档写的"mcpServers 白名单"与实况不符 |
| 2026-10-16 | 技术选型：零第三方依赖 + `sqlite3` + `argparse` + 自写渲染器 | 见 `plan/02` §一 弃选项理由 |
| 2026-10-16 | **M6 才建远端仓** | skill 建议；代价是首推 CI 需预算诊断轮（D7） |
